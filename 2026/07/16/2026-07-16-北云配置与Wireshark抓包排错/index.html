一、问题总览

# 问题 根因 解决
1 BY_Connect TCP 连不上 IMU DTU 换移动卡后，以太网段变了，需要重新配 IP 重新 AT 指令配网段
2 Wireshark 抓不到雷达数据 测试前没提前打开 Wireshark 对应网口 先开抓包再启设备

二、问题 1：北云 IMU TCP 连接失败

现象

  • 串口 AT 指令全部发送成功
  • BY_Connect 切换到 TCP 模式，填 192.168.86.72:2222，点 Open → 打开失败

排错

步骤 检查项 结论
1 笔记本 IP 设好了吗 已设 192.168.86.88 ✅
2 网线连交换机了吗 已连 ✅
3 IMU ENET 转接器 Link 灯亮吗 亮 ✅
4 DTU 换卡后配置改了吗 ⚠️ 换了移动卡，运营商不变但网段可能变了

根因

DTU 换卡后，即使同是移动卡，数据中心的以太网段可能变化。原来的 192.168.86.x 网段不一定能直接用，需要确认 DTU 配置后重新配 IMU 的静态 IP 使其在正确网段。

三、问题 2：Wireshark 抓包时机

错误做法

❌ 设备已经在跑了，才打开 Wireshark 抓包

正确做法

✅ 先打开 Wireshark，选好对应网口，点开始抓包，再启动/接入设备

步骤 操作
1 打开 Wireshark
2 双击对应网口（以太网）开始捕获
3 看到数据开始滚动了，再启动雷达/IMU
4 确认抓到目标数据包
5 停止捕获 → 文件 → 另存为

为什么

雷达/IMU 的数据是实时广播的，Wireshark 不会回溯你没抓到的部分。先开抓包才能从设备启动的第一帧开始完整记录。

四、问题 3：pcap 导出格式

操作

  1. 抓包完成后点击红色停止按钮
  2. 文件 → 另存为 → 选择 Wireshark/tcpdump - pcap 格式
  3. 不要存成 .pcapng（默认格式），除非对方明确要 pcapng

常用导出场景

场景 格式 说明
雷达标定（静态/动态） .pcap 发给工程师做标定
激光地图绘制 .pcap 录制后导入建图工具
自己分析查看 .pcapng 保留更多元数据

五、经验教训

  • DTU 换卡 = 网段可能变，不是同运营商就不用重配，而是网段要重新确认
  • Wireshark 先开后测，养成肌肉记忆
  • BY_Connect TCP 连不上时，先检查笔记本 IP → 网线 → IMU IP 三个环节，不要反复试 AT 指令
  • pcap 是通用格式，发给别人、导入工具都用 pcap，不要存 pcapng
